# Content plan — spec

**Purpose.** Fix three things: how the site is organized (information architecture + sitemap), how
its copy is written (voice — this is voice's one home), and the repeatable pattern every project
write-up follows so each is consistent and the UI always carries the needed information.

## Interview

### Part 1 — Information architecture

**Rounds:** ask choices ≤4 at a time (AskUserQuestion's cap) — e.g. site shape · navigation · how
work is surfaced · case-study depth in one round, optional pages with the next. The IA can be
**gated by the site concept**; if the concept isn't chosen, defer the affected parts with
`> Deferred — <what's needed>`.

#### [CHOICE] Site shape
- Single-page (one scroll, anchor nav)
- One-scroll home that links out to multi-page case studies — **(Recommended — skimmable front door plus real depth and shareable URLs)**
- Fully multi-page

#### [CHOICE] Navigation
- Minimal sticky top nav, ~3 items (Work · About · Contact) — **(Recommended — three items read instantly; more adds load)**
- Fuller nav (4–7 items)
- In-page scroll nav only

#### [CHOICE] How work is surfaced
- A few deep case studies + a range gallery — **(Recommended — flagship case studies carry the thesis; a gallery proves breadth without diluting quality)**
- 3–5 curated case studies only
- Everything at equal weight

#### [CHOICE] Case-study depth
- Scannable overview + optional deep read — **(Recommended — serves the 2–5 min skim and the engaged reader)**
- Short summary only
- Long-form only

#### [CHOICE] Optional pages
- Core only (Work, About, Contact) + downloadable résumé — **(Recommended — add more only if you'll keep it current)**
- Add Writing/Blog
- Add Now / Uses

The hero must convey five things: who you are + what you do, a value-driven headline, a proof
signal, one specific call to action, and work shown by example.

### Part 2 — Voice (its one home)

**Brief-aware:** factor the brief's intent — a job search may sell (market the work, don't
oversell); a personal showcase leans understated.

#### [OPEN] Bar test
> "Describe what you do, and one project you're proud of, to a friend at a bar — out loud, then
> write it down. This captures your real rhythm before self-editing."

#### [OPEN] Three adjectives + anti-words
> "Three words you'd want a stranger to use after reading your site — and for each, the anti-word
> you'd hate to hear."

#### [OPEN] Never sound like
> "Finish: 'I never want my writing to come across as ______.' Paste a cliché or a line of your
> own that makes you wince."

#### [CHOICE] Formality
- Polished / professional
- Conversational but precise — **(Recommended — human while keeping credibility)**
- Loose / playful

#### [CHOICE] Person & tense
- First person, present — "I design…" — **(Recommended — authentic and active for a personal site)**
- Third person — "[Name] designs…"
- Second person — addressing the visitor

#### [CHOICE] Sentence rhythm
- Longer, considered
- Short and varied, scannable — **(Recommended — people scan before they read; hierarchy by weight)**
- Punchy fragments

#### [CHOICE] Contractions & jargon
- Contractions on; plain language; jargon only when it's the reader's own word — **(Recommended — reads human; restrained jargon shows you can explain craft)**
- No contractions; precise technical vocabulary
- Casual throughout

#### [CHOICE] Humor
- None — let the work speak
- Dry, sparing, one deliberate wink — **(Recommended — humor as restraint, not decoration)**
- Frequent and playful

Produce a short voice chart: one row per trait, with a concrete do / don't.

### Part 3 — Project-display rules

#### [CHOICE] Narrative pattern to standardize on
- Expanded arc: Overview/Role → Problem → Process → Solution → Outcome → Reflection — **(Recommended — surfaces how you think; Problem→Solution→Impact falls out as the card summary)**
- Compact Problem → Solution → Impact
- STAR (Situation, Task, Action, Result)

#### [CHOICE] Card fields
- Thumbnail + title + one-liner + tags + year — **(Recommended — maximally scannable, label always visible)**
- Image-only grid, metadata on hover
- Text-forward list rows

#### [CHOICE] How strict is "impact"?
- Required: a metric OR a validated learning — **(Recommended — honest across project types, no fabricated numbers)**
- Required: a quantified metric
- Optional

Define a mandatory per-project field schema — required fields always present, optional fields
render only when supplied — so write-ups stay consistent and the UI never lacks what it needs.

## Outline
1. Information architecture — site shape, sitemap, navigation, projects surfaced, hero contents.
2. Voice — the chart (traits + do/don't) and the mechanical settings.
3. Project-display rules — the standard pattern, the card fields, the impact rule, the per-project
   field schema.

## Acceptance test
- [ ] A site shape and a sitemap are chosen.
- [ ] The hero plan covers all five required things.
- [ ] Voice has concrete do/don't pairs, not just adjectives.
- [ ] The project pattern is fixed, with a mandatory-field schema (required vs optional).
- [ ] Card fields are a subset of the project schema (the card is a projection).
- [ ] Sample copy passes the read-aloud test.
