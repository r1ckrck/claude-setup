# Working-folder schema

Outputs live under `./docs/figma/` relative to the project root. Three levels, dual format:
**JSON is the source of truth** (the engine diffs and merges against it); **markdown is a
derived view** (regenerated by `render`, never hand-edited). Files are keyed by immutable
IDs — `project_id` and the Figma file **key** — not display names, which change and aren't
unique.

```
docs/figma/
├── README.md                       # hand-written; explains the folder, says "don't hand-edit"
├── index.json / index.md           # team level
└── <project-slug>/
    ├── project.json / project.md   # project level
    └── files/
        ├── <file-key>.json / .md   # per-file detail
```

`<project-slug>` = lowercased, hyphenated project name.

## index — team level

`index.json`:
- `team_id`, `team_name`
- `whoami` — authenticated handle (from the MCP whoami), optional
- `last_refreshed` — ISO-8601 UTC
- `projects[]`: `project_id`, `name`, `slug`, `file_count`, `last_project_refresh`

## project — `<project-slug>/project.json`

- `project_id`, `name`, `slug`, `last_refreshed`
- `files[]`:
  - `file_key`, `name`
  - `thumbnail_url` — stored as a string; the image is not downloaded
  - `last_modified` — Figma's value, the refresh signal
  - `last_pulled` — when this skill last deepened the file (null until a lens/meta pass)
  - `depth` — `map-only` | `metadata` | `full`

## per-file — `<project-slug>/files/<file-key>.json`

The rich detail. This is where "detailed, not shallow" is enforced — capture every listed
field when you pull a level, don't skim the top.

- **Identity:** `file_key`, `name`, `figma_url`, `last_modified`, `version`, `last_pulled`,
  `source` (`rest` | `mcp`), `depth`
- **structure** (MCP `get_metadata`): `pages[]` each with `name`, `id`, and top-level
  `nodes[]` (`id`, `name`, `type`)
- **components / component_sets / styles** (REST file-level, or team-level + MCP
  `get_libraries`): each item's `key`, `name`, `description`/`style_type`,
  `containing_frame`
- **variables** (MCP `get_variable_defs` ONLY — never REST): `collections[]`, `variables[]`
  (`name`, `type`, resolved value per mode); annotate `source: mcp`
- **Provenance:** `version_history[]` (`id`, `label`, `created_at`, `user`), `comments_count`
- **Staleness:** `is_stale` is derived at render time — true when `last_modified` is newer
  than `last_pulled`

## Refresh & dedup

Refresh is a pure diff: incoming `last_modified` vs cached `last_pulled`. Equal means a
no-op — skip the call and report "unchanged." Files are stored once per `file_key`, so the
same file is never duplicated. The engine's per-file writes top-level-merge, so REST fields
and agent-added MCP fields (`structure`, `variables`, `libraries`) coexist without
clobbering. Generated files carry current state only — no history, no meta-comments.
